# 合集批处理与存量知识问答 — 需求规格

| 字段 | 值 |
|------|----|
| slug | issue-13 |
| Profile | fullstack |
| 需求来源 | GitHub Issue #13 |
| 创建时间 | 2026-09-01 10:00 |

## 1. 背景与目标

解决合集只能处理首条、批量摘要可能收到空输入、历史笔记不能重复问答且对话刷新丢失的问题。

## 2. 用户故事

| 角色 | 我想要 | 以便 | 优先级 |
|------|--------|------|--------|
| ViNote 用户 | 展开并勾选合集视频 | 批量生成笔记 | P0 |
| ViNote 用户 | 重做笔记、摘要和导图 | 修复偶发错误产物 | P0 |
| ViNote 用户 | 选择少量历史笔记进行多轮问答 | 复用已沉淀内容 | P0 |

## 3. 范围

**本次做：** 合集展开、最多 20 条提交；1-5 条历史笔记问答；SQLite 会话消息；产物重生成；空内容保护。

**本次不做：** 全库向量检索、知识图谱、修改现有单视频下载行为。

## 4. 主流程

```text
合集链接 → 展开勾选 → 现有批处理 → SQLite 笔记
历史勾选 → 创建会话 → 加载原文 → 流式多轮问答 → SQLite 消息
历史笔记 → 选择重生成层级 → 原子替换 Markdown → 更新 SQLite 索引
```

## 5. 数据与接口契约

| Scope | 实体/接口/字段 | 类型 | 说明 |
|-------|----------------|------|------|
| backend | qa_sessions / sources / messages | SQLite | 会话、来源和消息 |
| backend | notes.raw_transcript_file | TEXT 可空 | 原始转录索引，兼容旧库 |
| shared | POST /api/playlists/expand | JSON | 只解析不下载 |
| shared | POST /api/notes/{id}/regenerate | JSON | 重生成指定产物 |
| shared | /api/qa/sessions/* | REST/SSE | 持久化知识问答 |

## 6. 异常与边界

| 场景 | 预期处理 |
|------|----------|
| 非 B站/YouTube 链接 | 400，不访问目标 |
| 合集超过 100 条 | 返回前 100 条并标记截断 |
| 单批超过 20 条 | 前后端共同拒绝 |
| 问答超过 5 个来源 | 400 |
| LLM 返回空整理结果 | 回退到基础清理后的原文 |
| 重生成失败 | 保留原文件和 SQLite 指针 |

## 7. 验收标准

| ID | 验收项 | 可观察判据 |
|----|--------|------------|
| AC-13-001 | 合集选择 | 解析后可勾选并提交最多 20 条到现有批处理 |
| AC-13-002 | 空内容保护 | 优化结果为空时摘要仍获得非空文本 |
| AC-13-003 | 重生成 | 历史页两种重生成操作成功后内容可重新读取 |
| AC-13-004 | 存量问答 | 1-5 条笔记可创建会话，刷新后恢复来源和消息 |

## 需求审视

- 根本问题：已有能力未在入口、产物和持久化层串联。
- 隐含假设：少量来源问答不需要向量数据库。
- 更小方案：合集只展开 URL 并复用批处理；重生成只重跑下游阶段。
- 复杂度边界：保持单视频接口、Markdown 存储和现有历史接口兼容。
